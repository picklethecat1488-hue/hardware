#### Description

Clicking on any PR past PR535 in the dashboard results in a 404 error.

#### Resolution Notes

1. Added `get_remote_pr_numbers()` in `GitEngine` (`src/provider/vcs/git_engine.py`) to query remote repository pull request heads via `ls-remote origin refs/pull/*/head` and cache the set of verified pull requests existing on GitHub.
2. In `_extract_pr_info()`, validated PR numbers extracted from local branch tags against remote pull requests: unsubmitted local PR branches (e.g. `pr535`..`pr540`) resolve to `pr_status = 'Local PR #<num>'` with `pr_url = None` to prevent generating 404 URLs.
3. Updated `get_branch_url()` to route uncreated PR branches to `/tree/<branch>` rather than non-existent `/pull/<num>` URLs.
4. Rendered `.pr-local-badge` styling in `src/provider/templates/diff_view.html.j2` with local fallback toast handlers on PR and branch badges.
5. In `onBranchBadgeClick()`, guarded PR URL opening by verifying `isRemote` status before navigating to GitHub pull requests.
6. Added dedicated regression unit test `test_regression_bug_212_pr_past_535_404_handling` in `src/tests/test_dashboard.py`.
