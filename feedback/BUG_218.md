#### Description

When I try to create a PR for the commit 4bc4bf09 I get the associated error in "Execution Logs and Tracebacks". If a PR already merged the commit into the tracking branch, can we hide the commit in the VCS window by default?

#### Resolution Notes

1. Updated `GitEngine.create_prs_for_commits` in `src/provider/vcs/git_engine.py` to use `git branch -a --points-at <commit>` instead of `--contains`, preventing ancestor commits from false-positive conflict detections with PR branches pointing to descendant commits.
2. Added detection of upstream tracking branch (`@{upstream}`, `origin/main`, `main`) in `GitEngine.get_smartlog_dag` and flagged merged commits using `is_merged` and `is_merged_into_tracking` fields on `CommitNodeModel`.
3. Updated PR creation to cleanly reject attempts to create PRs for commits already merged into the tracking branch.
4. Added `#smartlogList.hide-merged` styling and default hidden state in `src/provider/templates/diff_view.html.j2`, tagging merged nodes with `.merged-commit` and adding a `✓ Merged` badge (`.node-badge-merged`).
5. Added `btnToggleMerged` button in the Smartlog header with localStorage persistence (`diffview_hide_merged`) allowing users to toggle merged commit visibility on demand.
6. Added automated regression test `test_regression_bug_218_pr_creation_points_at_and_merged_commits_hidden` in `src/tests/test_dashboard.py`.
