#### Description

When the dashboard is opened the first time, the dashboard should sync SQLite databases committed feedback files. Add a modal loading experience for this stage so that bugs and code review feedback are populated in database prior to showing the main VCS UI.

#### Resolution Notes

1. Added `initial_sync_done: bool = False` to `DiffViewSessionModel` in `src/model/vcs.py`.
2. Initialized `self.initial_sync_done: bool = False` in `DashboardServer` (`src/provider/dashboard/server.py`), populated it in `build_session()`, and updated `sync_feedback()` to set `self.initial_sync_done = True`.
3. Added `/api/sync_status` GET endpoint returning current synchronization status and exposed `/api/initial_sync` alias in `do_POST`.
4. Added Quake themed modal loading screen `#syncModalOverlay` in `src/provider/templates/diff_view.html.j2` with animated glowing progress bar (`#syncProgressBar`, `#syncProgressPercent`) and dynamic status feedback (`#syncStatusText`).
5. Added client-side orchestrator `performInitialSync()` which automatically triggers `/api/sync_feedback` on `DOMContentLoaded` when `initial_sync_done` is false, updates progress indicators, and reloads/updates the view with fully populated SQLite bug tags and review items.
6. Added manual `[⚡ Sync DB]` toolbar button allowing developers to re-synchronize databases on demand.
7. Added unit regression test `test_regression_bug_188_initial_sqlite_sync_loading_modal` in `src/tests/test_dashboard.py`.
