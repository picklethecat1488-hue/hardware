#### Description

Similarly to how the `sl` command is implemented:
Update the sync behavior on the dashboard to indicate in the UI list where the top of the ancestor branch (.e.g. main) 
Add a rebase button to the dashboard, when we rebase, the ancestor branch marker is updated to all recently pushed commits
"Old" commits, which were already merged into the ancestor branch, are not shown in the commit UI, only the top of the ancestor branch is shown

#### Resolution Walkthrough

1. **Smartlog Ancestor Top & Merged Commit Pruning (`src/model/vcs.py`, `src/provider/vcs/git_engine.py`)**:
   - Added `is_ancestor_top: bool = False` and `ancestor_name: Optional[str] = None` to `CommitNodeModel`.
   - Updated `GitEngine.get_smartlog_dag()` to automatically discover the upstream ancestor branch (e.g. `origin/main` or `main`) and calculate the merge-base with the current topic branch.
   - Identified the divergence commit as the ancestor top (`is_ancestor_top = True`, `ancestor_name = "main"`).
   - In accordance with Sapling (`sl`) behavior, pruned older commits already merged into the ancestor branch so only unmerged commits and the top of the ancestor branch are presented in the commit tree.
2. **Rebase Integration (`src/provider/vcs/git_engine.py`, `src/provider/dashboard/server.py`, `diff_view.html.j2`)**:
   - Added `GitEngine.rebase_branch(upstream)` supporting automatic rebasing onto tracking branch or `origin/main` / `main`, cleanly aborting on conflicts to preserve repository state.
   - Exposed `POST /api/rebase` in `DashboardServer`.
   - Added `⤵ Rebase` button (`#btnRebase`) to the HUD toolbar with interactive spinner and toast notifications.
   - Highlighted ancestor top node in Smartlog with `.ancestor-top-node` border and `📌 main` badge (`.node-badge-ancestor`).
3. **Regression Tests**:
   - Added `test_regression_bug_213_ancestor_top_marker_merged_pruning_and_rebase` in `src/tests/test_dashboard.py`.
